# Project Cover Pixel Redesign Design

## Goal

Replace the current mismatched project cover images with a new unified set of pixel-art product covers that better match the actual meaning of each project and feel consistent across the projects page.

## Approved Direction

Use a structured pixel dashboard card style for all five project covers. Each image should feel like a stylized product cover that clearly communicates the project domain through interface-like composition, while keeping a coherent pixel-art series look across the whole set.

## Audience

- Recruiters and hiring managers scanning the projects page quickly.
- General visitors who need a more immediate visual cue for what each project is.
- Jabin as the site owner, who needs the imagery to feel more truthful to the actual work.

## Scope

- Replace all five current project cover images.
- Keep a unified pixel-art style across the full set.
- Design each cover around the real project domain and product meaning.
- Produce images suitable for the existing project cards and showcase layouts.

## Out Of Scope

- Rewriting the projects page structure again.
- Highly detailed readable UI text inside the images.
- Moving away from pixel art into photoreal, flat vector, or abstract poster styles.
- One-off style experimentation per project that breaks set consistency.

## Problem To Solve

The current project images do not map closely enough to the actual project content. Some projects reuse the same image, and some covers imply the wrong kind of product. This weakens trust and makes the projects page feel less intentional.

## Visual Direction

### Style

- Pixel art
- Product-cover oriented
- Clean, modern, and structured
- More like a stylized dashboard or app cover than a pure game scene

### Composition

- Horizontal cover images suitable for the website’s existing cards
- Clear main panel or main UI surface
- One dominant subject or product identity per cover
- 1 to 3 supporting UI modules or visual cues around the main product

### Series Consistency

All five covers should share:

- similar framing logic
- similar pixel density
- similar lighting and shading logic
- similar border and card language
- a restrained, coherent palette family

## Project-Specific Cover Direction

### 1. The Oneness Association

Intent:
- live production website
- member platform
- trustworthy, calm, modern, community-oriented

Visual cues:
- pixel website homepage layout
- content sections and navigation
- membership or login panel feel
- warm, welcoming, non-profit tone

Avoid:
- overly mystical or heavy religious symbolism
- random abstract spirituality that obscures the product

### 2. Schedora

Intent:
- internal workflow platform
- property scheduling
- inspection and reporting operations

Visual cues:
- calendar blocks
- task routing
- property or building icons
- checklist/report panels
- operational dashboard feel

Avoid:
- making it look like a generic CRM
- making it look like a public consumer app

### 3. FinanceBro

Intent:
- AI investment assistant
- Telegram-based analysis experience
- portfolio/risk/options context

Visual cues:
- market charts
- portfolio widgets
- AI assistant/chat panel
- options or analytics board
- Telegram or messaging-inspired interaction feel

Avoid:
- making it look like a trading execution interface
- casino, hype-trader, or meme-finance aesthetics

### 4. Medimate

Intent:
- digital pharmacy system
- multi-platform product
- medication recognition and pharmacy operations

Visual cues:
- pharmacy dashboard
- medicine/product scan panel
- order or cart flow
- healthcare-themed but still product-oriented interface

Avoid:
- cartoon medical mascots
- overly clinical hospital imagery disconnected from software

### 5. Musichat

Intent:
- social music product
- AI/music/chat mix
- more playful than the others, but still in the same family

Visual cues:
- music player panel
- playlist/feed
- chat interface
- social/discovery UI elements

Avoid:
- making it look too childish
- drifting too far into pure entertainment poster over product cover

## Content And Text Rules

- Do not rely on small readable text inside the generated images.
- If text appears, it should be minimal and non-essential.
- The meaning must come from composition, iconography, and interface structure rather than exact wording.

## Technical Output Direction

- Produce five cover images.
- Keep aspect ratio appropriate for the current website project cards.
- Save as website-ready bitmap assets.
- Replace the existing cover files or add new files and update project references accordingly.

## Success Criteria

- Each cover clearly feels connected to the actual project it represents.
- The five covers look like one intentional series.
- The projects page gains stronger first-glance clarity and polish.
- The imagery supports the site instead of confusing the project narrative.

## Testing

- Visually verify each cover against its project meaning.
- Check the set together for consistency.
- Confirm the images look good inside the current project cards on desktop and mobile.
